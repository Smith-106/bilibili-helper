# bilibili哔哩哔哩下载助手

浏览器扩展（Manifest V3），帮助你下载 B 站视频，包括「能看不能缓存」的版权受限番剧、电影、影视、电视剧等内容。

- **商店名称**：bilibili哔哩哔哩下载助手
- **当前版本**：`3.0.20`
- **清单版本**：Manifest V3
- **运行方式**：纯前端注入（content script + ffmpeg wasm 合并音视频），无后端依赖

---

## 功能特性

| 功能 | 说明 |
|------|------|
| 单视频下载 | 解析当前播放视频，给出可下载地址（高级模式自动重命名并合并音视频） |
| 兼容模式 | 直接走浏览器默认下载，资源占用小（不支持自动重命名/合并） |
| 批量下载合集 | 一键批量下载当前 `ugc_season` 合集全部集数 |
| 批量下载 UP 主全部视频 | 在视频页一键拉取该 UP 主全部投稿（legacy `x/space/arc/search` 分页）并逐集下载；列表下方常驻**完整性条**（预期/实际/缺/完整·部分·缓存·冷却/缓存时间），部分或缓存时可一键**重抓完整列表** |
| 清晰度跟随 | 默认跟随播放器清晰度，可在面板中固定 qn（16–125） |
| 断点续传 | 已下载集数持久化到 `localStorage`，支持「跳过上次已下载」 |
| 失败冷却 | 连续失败自动延长间隔，附失败清单一键复制 |

## 安装

1. Chrome / Edge 打开 `chrome://extensions`（Edge 为 `edge://extensions`）。
2. 开启「开发人员模式」→「加载已解压的扩展程序」→ 选择本仓库目录。
3. 打开任意 `bilibili.com/video/...` 页面，页面底部会出现「B站下载助手」面板。

> 商店版本见 README 顶部图标跳转链接（脚本内嵌 Chrome Web Store / Edge Add-ons 地址）。

## 使用

### 单集
打开视频页 → 面板自动解析 → 点击下载链接（高级模式）或右键另存为（兼容模式）。

### 批量下载合集
在含合集（`ugc_season`）的视频页点击 **「批量下载合集」**。

### 批量下载 UP 主全部视频
在该 UP 主任一视频页点击 **「批量下载该UP主全部视频」**。扩展会按 30 条/页遍历 `x/space/arc/search`，集齐后开始逐集下载。

列表拉取完成后，按钮下方常驻**完整性条**：`完整性：预期Y / 实际N / 缺M / 完整|部分|缓存|冷却 / 缓存<时间>`——Y 取服务端 `page.count` 快照，N 为实际抓到数。状态为部分/缓存时附带**「重抓完整列表」**按钮（直接再跑一次列表腿，冷却期内零请求只提示剩余时间）。

**如何判定提完**：完整性条显示 `缺0 / 完整` + 开始下载行 `共N个视频，开始批量下载…`（无后缀）+ 结束行 `🎉 全部完成：成功N 跳过0 失败0`，三者一致即真提完；若开始行带 `（部分列表…）`/`（缓存列表…）` 后缀，说明列表被风控截断或走的老缓存，点重抓或等冷却后再试。

**速度档**（`localStorage.bilibili_helper_batch_delay`，默认 3s/集）：快速 1s / 标准 3s / 保守 6s / 最稳 12s / 超稳 18s（被限流时用）。列表页间隔与速度档联动（默认约 4.5–6s，超稳档约 8.5–10s），请求受限恢复后自动再放慢。越慢越不易触发风控。

## 风控与安全设计（R3 语义）

为降低触发 B 站风控（`-799 请求过于频繁` / HTTP 412 / `-352` / `-403`）的概率，扩展内置以下行为约束：

| 约束 | 实现 |
|------|------|
| 分页间隔 | 起步停顿 2–3s；页间隔与速度档联动（快速约 4.5–6s / 标准约 4.5–6s / 保守约 5.5–7s / 最稳约 7–8.5s / 超稳约 8.5–10s）；请求受限后自适应再 +2s/次（上限 +6s） |
| `-799`/网络异常退避 | 分两档：**pn1 双败 fast-fail**（首屏连续 2 次失败只重试 1 次约 12s，随即进 15min 冷却、期间零请求）；**中途分页**有界递增退避最多 4 次（约 20/26/32/38s，已自动放慢）后继续；退避耗尽写 15min 冷却并按已抓页增量缓存返回 |
| 兜底策略 | pn1 失败时优先用上次成功缓存（`partial`+缓存标记）继续；无缓存则进 15min 冷却并提示，不再空转重试。中途失败退避耗尽后按已抓页返回 `partial` 或空。**绝不**退化为单条目批量（已移除 `top/arc` 单条回填） |
| 上限 | 最多遍历 `t>=40` 页 |
| 去重 | `seen` Set 按 `bvid` 去重 |
| 零抛错 | 列表腿不向上抛错，统一走 partial 降级 |
| 批量节奏 | 每集 `delay + jitter`，连续失败 `>=2` 自动延长至 `delay*3` |
| 持久化 | `bilibili_helper_batch_done` 记录已完成 `cid`，支持跳过 |

> **注意**：正常使用节奏下不主动触发风控。若首屏即 `-799`（一点按钮就“请求受限”），说明该号/IP 已被服务端冷却——脚本只会重试 1 次然后进入 15 分钟冷却（期间零请求），请勿反复点击；可等冷却后用缓存继续，或换网络后再试。批量下载仍受 B 站服务端配额影响，请合理控制频率，勿短时间连续大批量。

## 验证（可复跑证据）

仓库内置零网络确定性验证门：

```bash
node --check bilibili-helper-content-script.js   # 语法
node evidence/verify-u1-bxd.mjs                  # 39 项 harness（静态+重放+预算场景+完整性）
node evidence/acceptance.mjs                     # 16 项验收门（R1/R2/R3）
```

`evidence/` 目录保留了真实抓包与全量扫描的轻量证据（view/pagelist/playurl/byte 各 1158/1158，risk=0）。UP 主列表完整性语义（`expected`/`partial`/`cached`/`cool`+`bx8` 常驻条）见 `docs/batch-download.md` 与 `docs/KNOWLEDGE.md` S10。详见 `docs/`。
