# 批量下载指南

## 批量下载合集

在含 `ugc_season` 合集的视频页，点击 **「批量下载合集」**。扩展枚举合集全部集数并逐集下载。

## 批量下载 UP 主全部视频

在该 UP 主任一视频页点击 **「批量下载该UP主全部视频」**。

### 完整性条（v3.0.20）：怎么知道“真的提完了”

列表拉取完成后，按钮下方常驻一行（与下载进度 `#batch-status` 分离，开始下载后也不会被覆盖）：

```
完整性：预期Y / 实际N / 缺M / 完整|部分|缓存|冷却 / 缓存<时间>  [重抓完整列表]
```

- **Y（预期）**：B 站 `page.count` 总数快照；**N（实际）**：本次实际抓到的去重条数；**M=Y-N**：缺数。
- **状态**：`完整`=Y==N 全量；`部分`=中途被风控截断（按已抓增量缓存返回）；`缓存`=用的上次成功缓存（`cacheTs` 为其时间）；`冷却`=本次零请求。
- **重抓完整列表**按钮仅在部分/缓存时出现，点击直接再跑一次列表腿（冷却期内零请求、只提示剩余时间）。

### 二次确认（v3.0.21）：缓存/部分不等下载完才发现

`Dv` 拿到缓存/部分列表且有数据时，先弹确认框（`window.confirm`）：`当前为缓存|部分列表：预期Y / 实际N / 缺M / 缓存<时间>。继续将只下载这N个，缺M个不会自动补。确定继续吗？（取消=停手，可稍候点「重抓完整列表」）`——点取消则停手复位（`#batch-status` 留“已取消…可点重抓”提示，不进下载循环）；点确定才继续。完整性条口径与判定三者一致不变。

判定口径（三者一致即真提完）：

1. 完整性条 `缺0 / 完整`；
2. 开始下载行 `共N个视频，开始批量下载…`（**无** `（部分列表…）`/`（缓存列表…）` 后缀）；
3. 结束行 `🎉 全部完成：成功N 跳过0 失败0`。

> 人工核数：F12 → Application → Local Storage → `bilibili_helper_uplist_<mid>`（`{ts, count, v}`，`v.length` 为实际抓到数，`count` 为服务端总数）；`bilibili_helper_uplist_cool_<mid>` 存在=15min 冷却期内。

- 列表来源：`x/space/arc/search?mid=<mid>&pn=N&ps=30&order=pubdate`（legacy 接口，匿名可用，无 wbi 签名）。实测确认：space HTML 为 SPA 空壳、dynamic feed 需鉴权、series/search-type 报 -400、top/arc 仅 1 条——**无可用的第二完整列表桶**，故本方案不换接口，只做节奏+冷却+缓存。
- 每页 30 条，起步停顿 2–3s 后开抓；页间隔与速度档联动（默认约 4.5–6s，超稳档约 8.5–10s），请求受限后自适应再放慢（+2s/次，上限 +6s）；最多 40 页。
- 按 `bvid` 去重收敛后进入下载循环；每成功抓一页即写增量缓存 `bilibili_helper_uplist_<mid>`。

### 速度档

| 档位 | 每集间隔 |
|------|----------|
| 快速 | ~1s |
| 标准 | ~3s（默认） |
| 保守 | ~6s |
| 最稳 | ~12s |
| 超稳 | ~18s（列表也被限流时用） |

> 间隔 = `delay*1000 + random*delay*500`；连续失败 ≥2 自动提升到 `delay*3`。

### -799 处理（v3.0.17 起，v3.0.18 防风控重设计，v3.0.19 中途加强）

分两档：

- **pn1 双败 fast-fail（v3.0.18）**：首屏（第 1 页，还没抓到任何视频）连续失败只重试 1 次（约 12s），再败即停——**不再空转 4 次退避**，并写入 15 分钟冷却标记，期间再次点击直接提示、不发任何请求。若有上次成功缓存，自动用缓存（标 `partial`+缓存）继续；无缓存则提示稍候再试。
- **中途分页（v3.0.19 加强）**：-799/网络异常 → 加长递增退避最多 4 次（约 20/26/32/38s，提示“已自动放慢”）后继续分页；每次退避都再放慢后续页间隔；退避耗尽写 15min 冷却并按已抓页增量缓存返回 partial（之前抓到的不丢，稍候可再试或用缓存继续）。
- **不再**退化为单条目批量（top/arc 单条回填已移除）。

> 一点按钮就“请求受限”= 该号/IP 已被服务端冷却。请勿反复点击（冷却期内点击零请求、只提示剩余时间）；等冷却过后自动恢复，或换网络后重试。

### 断点续传

`bilibili_helper_batch_done` 持久化已完成 `cid`；勾选「跳过上次已下载」即可续跑。「清空记录」可重置。批量结束后「跳过上次已下载」行显隐即时刷新，无需重渲染面板。

### 失败重试与分类（v3.0.24）：不用全量重跑

结束行带失败数时（`全部完成：成功N 跳过M 失败K（需会员/登录a，其他b）`），状态区并排两个按钮：

- **复制失败清单**：`序号. 标题 — 原因` 文本，剪贴板不可用时降级为 `prompt` 手动复制。
- **重试失败 K 集**：仅重跑本轮失败项（`bx0.failItems` 引用直传，不重新拉列表、不耗列表配额）；失败项此前已从已下载记录剔除，与「跳过上次已下载」不冲突。重试轮开始行标注“本轮为失败重试，仅 N 集”；重试仍失败可继续点，直至收敛。

失败分两类计数：`需会员/登录`（-10403/大会员/充电/登录——这类重试也过不了，先登录/充电再说）与 `其他`（网络/风控/解析，值得重试）。

### 开始行 ETA（v3.0.24）：1159 集要跑多久心里有数

开始下载时日志行追加 `预计集间等待约X分钟（不含下载/合并耗时）`（集数 × 速度档 × 1.25）。下载+ffmpeg 合并耗时另计，大文件/高级模式会更久。
